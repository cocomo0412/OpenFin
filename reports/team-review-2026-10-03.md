# OpenFin 프로젝트팀 첫 개선 활동

2026년 10월 3일 사용자 요청에 따라 총괄 PM, 사용자 경험, 금융 데이터와 온톨로지, 개발, 품질 검증의 5명 AI 팀을 구성했다. 첫 활동은 현재 공개 서비스의 검색 문제를 평가하고 재현 가능한 결함을 개선하는 것이다. 팀의 역할과 반복 절차는 [운영 지침](../AGENTS.md)에 기록했다.

작업 기준은 `a058aafe`이며, 독립 작업 공간의 `codex/team-improvement-20261003` 브랜치에서 진행한다. 기존 OpenFin 채팅의 PR 갱신 작업과 미커밋 변경은 보존했다.

## 첫 개선 선정

| 담당 | 확인한 문제 | 결정과 이유 |
| --- | --- | --- |
| 사용자 경험 | 기본 탐색기에서 검색어만 입력하면 검색 자료를 불러오지 않아 결과가 없음 | 첫 사용 과업을 막으므로 우선 수정 |
| 품질 검증 | 무료 MCP가 아홉 번째 이후 검색 단어를 무시함 | 조건 누락을 재현했고 수정 범위가 작아 우선 수정 |
| 금융 데이터와 온톨로지 | 붙여 쓴 제목 검색이 실패하고 정확한 제목이 다른 항목보다 뒤에 표시됨 | 같은 검색 함수에서 개선할 수 있어 함께 수정 |
| 개발 | 위 검색 문제의 구현 범위와 기존 제약 검토 | 모든 검색 조건, 120자 제한, 최대 10건, 출처 계약 보존 |
| 총괄 PM | 영향과 검증 가능성 비교 | 검색 개선을 첫 활동으로 선정하고 독립 검증 배정 |

## 수정 내용

- 탐색기는 첫 유효 검색 입력에서 검색 인덱스를 불러온다. 초기 공백 입력은 안내를 유지하고, 연속 입력은 최신 검색어를 사용하며, 로딩 실패는 재시도 방법을 안내한다.
- 무료 MCP 검색은 아홉 번째 이후 단어도 검사한다. 예전에는 `월세`를 여덟 번 입력한 뒤 존재하지 않는 조건을 추가해도 24건을 반환했다. 수정 후에는 모든 조건을 검사해 결과 없음으로 처리한다.
- `월세액세액공제`, `보험료세액공제`처럼 붙여 쓴 제목도 검색한다. 공백 제거 보조 검색은 제목에만 적용해 본문과 필드 경계를 연결하지 않는다.
- `보험료 세액공제` 검색에서는 정확한 제목의 `credit.insurance-premium`을 먼저 표시한다.
- 독립 품질 검토에서 첫 검색 로딩 중 선택한 분야가 로딩 완료 후 전체로 바뀌는 추가 문제를 재현해 수정했다. 이후 해당 분야에서 입력한 새 검색어도 즉시 반영하고, 뒤늦은 로딩 실패가 현재 화면 안내를 덮지 않도록 보완했다.
- 새 검색 회귀 검사를 실행하는 `OpenFin search quality` 검증 workflow를 추가했다. 이 workflow에는 배포 단계가 없다.

## 검증 상태

관련 검사 22개와 TypeScript 검사, JavaScript 문법 검사, 변경 형식 검사가 통과했다. 검색 검사는 MCP 8개와 화면 14개로 구성된다. 뒤늦은 전역 로딩 중 선택한 분야에서 재검색하는 사례는 추가 검사에서 수정 전 실패와 수정 후 통과를 확인했다. 품질 담당이 최종 수정과 검증 workflow의 정적 구성을 독립 검토하고, 같은 검사 명령으로 22개 통과를 확인해 이번 변경을 승인했다.

실제 브라우저 조작, GitHub Actions 실행, 운영 배포 검증은 아직 수행하지 않았다. 화면 검사는 실제 앱 코드를 가상 DOM과 지연 응답으로 실행하는 회귀 검사다. 원격 저장소 및 운영 서비스에는 아직 반영하지 않았다.
