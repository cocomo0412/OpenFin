# OpenFin 프로젝트팀 첫 개선 활동

2026년 10월 3일 사용자 요청에 따라 총괄 PM, 사용자 경험, 금융 데이터와 온톨로지, 개발, 품질 검증의 5명 AI 팀을 구성했다. 첫 활동은 현재 공개 서비스의 검색 문제를 평가하고 재현 가능한 결함을 개선하는 것이다. 팀의 역할과 반복 절차는 [운영 지침](../AGENTS.md)에 기록했다.

작업 기준은 `a058aafe`이며, 독립 작업 공간의 `codex/team-improvement-20261003` 브랜치에서 진행한다. 기존 OpenFin 채팅의 PR 갱신 작업과 미커밋 변경은 보존했다.

## 첫 개선 선정

| 담당 | 확인한 문제 | 결정과 이유 |
| --- | --- | --- |
| 사용자 경험 | 기본 탐색기에서 검색어만 입력하면 검색 자료를 불러오지 않아 결과가 없음 | 첫 사용 과업을 막으므로 우선 수정 |
| 품질 검증 | 무료 MCP가 아홉 번째 이후 검색 단어를 무시함 | 조건 누락을 재현했고 수정 범위가 작아 우선 수정 |
| 금융 데이터와 온톨로지 | 붙여 쓴 제목 검색이 실패하고 정확한 제목이 다른 항목보다 뒤에 표시됨 | 같은 검색 함수에서 개선할 수 있어 함께 수정 |
| 개발 | 위 검색 문제의 구현 범위와 기존 제약 검토 | 모든 검색 조건, 120자 제한, 최대 10건, 출처 계약 보존 |
| 총괄 PM | 영향과 검증 가능성 비교 | 검색 개선을 첫 활동으로 선정하고 독립 검증 배정 |

## 수정 내용

- 탐색기는 첫 유효 검색 입력에서 검색 인덱스를 불러온다. 초기 공백 입력은 안내를 유지하고, 연속 입력은 최신 검색어를 사용하며, 로딩 실패는 재시도 방법을 안내한다.
- 무료 MCP 검색은 아홉 번째 이후 단어도 검사한다. 예전에는 `월세`를 여덟 번 입력한 뒤 존재하지 않는 조건을 추가해도 24건을 반환했다. 수정 후에는 모든 조건을 검사해 결과 없음으로 처리한다.
- `월세액세액공제`, `보험료세액공제`처럼 붙여 쓴 제목도 검색한다. 공백 제거 보조 검색은 제목에만 적용해 본문과 필드 경계를 연결하지 않는다.
- `보험료 세액공제` 검색에서는 정확한 제목의 `credit.insurance-premium`을 먼저 표시한다.
- 독립 품질 검토에서 첫 검색 로딩 중 선택한 분야가 로딩 완료 후 전체로 바뀌는 추가 문제를 재현해 수정했다. 이후 해당 분야에서 입력한 새 검색어도 즉시 반영하고, 뒤늦은 로딩 실패가 현재 화면 안내를 덮지 않도록 보완했다.
- 새 검색 회귀 검사를 실행하는 `OpenFin search quality` 검증 workflow를 추가했다. 이 workflow에는 배포 단계가 없다.

## 검증 상태

관련 검사 22개와 TypeScript 검사, JavaScript 문법 검사, 변경 형식 검사가 통과했다. 검색 검사는 MCP 8개와 화면 14개로 구성된다. 뒤늦은 전역 로딩 중 선택한 분야에서 재검색하는 사례는 추가 검사에서 수정 전 실패와 수정 후 통과를 확인했다. 품질 담당이 최종 수정과 검증 workflow의 정적 구성을 독립 검토하고, 같은 검사 명령으로 22개 통과를 확인해 이번 변경을 승인했다.

실제 브라우저 조작, GitHub Actions 실행, 운영 배포 검증은 아직 수행하지 않았다. 화면 검사는 실제 앱 코드를 가상 DOM과 지연 응답으로 실행하는 회귀 검사다. 원격 저장소 및 운영 서비스에는 아직 반영하지 않았다.

## 2026-10-06 자료 현황 화면과 배포 구분

사용자 요청으로 자료 현황 제목과 설명을 일반 사용자 표현으로 변경했다. manifest JSON 링크와 카드의 내부 파일명을 제거했으며 개발자용 접기 영역도 만들지 않았다. 자료 수와 원자료 수집일·파일 갱신일 구분은 유지한다. API 키는 비공개 수집 환경·서버 secret에만 두고 공개 파일·브라우저 요청·URL·로그에 포함하지 않는 원칙을 지침과 매뉴얼 1.1.1에 명시했다.

MCP workflow의 push 경로를 MCP 파일·세금 원자료·workflow로 제한했다. 독립 QA에서 후속 홈페이지 커밋이 진행 중인 MCP 배포를 막는 문제를 발견해, 최신 main과 MCP 입력 전체가 동일한 경우에는 검증된 번들을 허용하도록 수정했다. 코드·세금 원자료·workflow·의존성 변경은 차단한다.

검증: 화면 관련 검사 14개, 배포 관련 검사 4개, JavaScript 구문·diff check, Wrangler 무료 번들 dry-run 통과. 브라우저에서 자료 카드 10개, 수정 문구와 JSON 링크·파일명 제거를 확인했다. dry-run이 재생성한 카탈로그는 이번 변경 범위가 아니므로 실행 전 상태로 복원했다. 품질 담당이 배포 조건과 문서를 독립 재검토해 승인했다.

보안 점검 범위: 두 로컬 체크아웃의 Git 추적 파일 8,876개/8,868개(각 공개 파일 7,250개)를 현재 로컬 자격증명 값 및 URL 인코딩값과 대조했다. 일치 값·인증값 포함 URL 후보·추적된 실제 .env 파일을 발견하지 못했다. 운영 manifest도 같은 대조에서 일치 값이 없었다. 비밀값은 출력·저장하지 않았다. Git 전체 과거 이력이나 알 수 없는 키까지 부재를 보장하는 검사는 아니다.

배포 판정: 화면 수정만 떼어 반영하면 홈페이지만 필요하다. 이번에는 MCP workflow와 배포 검사 자체도 변경하므로 전체 변경 묶음을 운영 반영할 때 MCP 검증·배포가 한 차례 필요하다. 이후 홈페이지만 변경할 때는 MCP 재배포를 건너뛴다. 기존 팀 브랜치의 미배포 MCP 검색 개선까지 포함하면 역시 MCP 배포 대상이다. 현재 결과는 로컬 수정·검증이며 원격 push·운영 배포는 수행하지 않았다.


## 2026-10-06 정보 검색 화면 개선

메인과 일관된 크림색 배경·녹색 선택 표시·분야별 파스텔색을 적용하고 제목과 여백을 줄여 검색창을 위로 올렸다. 처음에는 전체 분야를 선택하며 유형·자료 상태·출처 안내를 한국어로 정리했다. 상세에서 내부 ID·checksum 등 불필요한 표시를 줄이고 자료 기준일·검토일·출처는 보존했다. 기존 상세의 원문 필드와 JSON 안내까지 모두 제거한 변경은 아니다.

120건 이후 더보기를 추가했다. 검색어·유형·분야가 바뀌면 표시 개수를 초기화하며 선택한 자료가 결과에서 사라지면 상세와 주소의 선택 표시도 지운다. 지연된 상세·출처 응답이 이전 선택을 되살리지 않는다. 좁은 화면에서는 상세로 이동하고 결과로 돌아가는 버튼을 제공한다. 결과 수는 상태 안내로, 선택 상태는 aria-pressed로 전달한다.

역할: UX 담당이 HTML·CSS, 총괄이 검색 동작과 통합, 독립 QA 담당이 회귀 검사와 최종 코드 검토를 수행했다. QA에서 지적한 더보기 후 화면 밖 포커스 문제는 기본 포커스 스크롤로 수정했다.

검증: JavaScript 문법·화면 회귀 17개·diff check 통과. 로컬 실제 브라우저에서 월세 124건의 120→124 표시, 신규행 포커스 가시성, 0건일 때 상세·hash 초기화 확인. 실제 CSS viewport 폭 487px에서 단열 배치·가로 넘침 없음·상세 포커스와 결과 복귀 확인(요청 viewport 390px과 앱의 실제 CSS 폭이 달랐으므로 390px 검증으로 기록하지 않음). 스크린리더 실제 낭독 검사는 수행하지 않았다. 독립 QA에서 추가 차단 문제 없음.

반영 범위: 로컬 구현·검증 완료. 이번 변경은 docs 화면과 관련 검사·활동 기록뿐이며 원격 push·운영 배포는 수행하지 않았다. 홈페이지 배포만 필요하고 MCP 재배포는 불필요하다. 원자료·수집일·API 요청·비밀 설정 변경 없음. 매뉴얼 절차 변경이 없어 매뉴얼 버전 1.1.1 유지.


### 정보 검색 제목 아이콘 추가

사용자 추가 요청으로 정보 검색 제목 옆에 홈 검색 버튼과 동일한 돋보기 SVG를 추가했다. 홈의 민트색 제목 배지와 크기·모서리·모바일 축소 규칙을 맞췄다. 장식 아이콘은 보조기술에서 제외하고 CSS 캐시 버전을 갱신했다. 실제 브라우저 표시·diff check 및 독립 QA 검토 완료. 로컬 반영이며 홈페이지 배포 전, MCP 재배포 불필요.
