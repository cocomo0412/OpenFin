# 운영 MCP 실제 조회 범위 확인

검사 시각: 2026-10-07 20:21 한국시간. 사용자 요청으로 운영 MCP에 공식 SDK를 사용해 연결·도구 목록·검색·개별 조회를 실행했다. 홈페이지 문구나 health만으로 판정하지 않았다.

- 주소: `https://openfin.cocomo0412.workers.dev/mcp`
- 서버: `openfin-free` 1.0.2
- 공개 도구: `search`, `fetch`, `exports`
- 실제 exports: `domain=tax`, `item_count=399`

세 상품은 공개 홈페이지 JSON에서 실제 ID를 읽은 후 같은 ID로 호출했다. 공통 오류는 `이 ID는 세금·공제 무료판 범위에 없습니다.`이다. 이번 호출에는 Cloudflare 자원 초과 오류가 없었다.

## 원인과 판단 범위

`mcp/scripts/build-free-catalog.mjs:4`가 세금 JSON 하나만 읽는다. 같은 파일 17·21행은 자체 제한 500개·600,000바이트를 적용한다. `mcp/src/free-catalog.ts`는 그 카탈로그만 색인·ID 맵으로 만들고, `mcp/src/free.ts:46`이 없는 ID에 범위 밖 오류를 반환한다. 따라서 현재 상품 조회 실패의 직접 원인은 MCP에 상품 자료가 포함되지 않은 구현이다.

과거 보관 문서에는 전체판 CPU 한도 문제가 기록되어 있다. `evidence/directive-completion/candidate-cpu-diagnosis.json`에 exceededCpu와 120건 중 3건 실패가 있으나, 해당 파일은 명시적으로 ‘Historical upstream evidence; identity redacted. Not evidence for current deployment.’라고 표시한다. **현재 cocomo0412 운영 환경에서 전체 자료를 처리하면 반드시 실패한다는 증거가 아니다.** 앞서 이를 현재 환경의 축소 원인으로 단정한 설명은 근거가 부족했다. 이번에는 과거 장애를 재현하지 않았으며 전체 분야 검색이 반드시 유료여야 한다고 판정하지 않는다.

[Cloudflare 공식 제한 문서](https://developers.cloudflare.com/workers/platform/limits/)를 확인했다. 무료 HTTP 요청 CPU 10ms·메모리 128MB 등 자원 한도가 있으며, CPU·메모리 초과 시 1102 오류로 구분된다. 세금 분야만 허용하는 플랫폼 정책은 아니며, 전체 분야 지원 가능 여부는 별도 구조·성능 검증이 필요하다. 이번 검사는 전체판 부하 시험이 아니다.

## 증적과 변경 범위

- [원응답 증적](mcp-live-scope.json): 도구 스키마·exports·검색·fetch 응답과 공개 상품 출처/ID.
- [재현 스크립트](probe-mcp-scope.mjs): 직접 실행할 때만 공개 읽기 요청을 수행하며 자동 실행·배포와 연결되지 않는다.
- 서비스 코드·자료·Cloudflare 설정을 바꾸거나 MCP를 배포하지 않았다. 검사 결과만 로컬 기록한다.
- 검사 도중 사용자가 소개문구 및 운영목적·하단의 오늘 변경 문구 원복을 요청했다. `docs/index.html` 전체를 이번 TRUST-01~03 조치 이전 `130d7edc` 버전으로 복원했다. 앞서 요청한 카드 간격 CSS는 보존했다. 이번 조사에서 MCP 범위나 코드·설정은 변경하지 않는다.

## 전체 자료 구현 가능성 추가 검토

서버·MCP 담당 `full_mcp_feasibility`가 코드·파일 크기·과거 증거를 읽기 전용으로 별도 검토했다.

- 전체판 `mcp/src/index.ts`, `mcp/src/tools/search.ts`, `mcp/src/tools/fetch.ts`에는 전체 manifest와 분야별 검색·ID 조회 구현이 존재한다. 현재 무료판 진입점과 연결되지 않았다. 전체 자료 MCP가 원리상 구현 불가능해서 제외된 것은 아니다.
- 무료 카탈로그 실제 크기는 223,780바이트·399건이며, 생성기의 500건·600,000바이트 제한은 프로젝트 자체 설정이다.
- 단순 전체판 재활성화에도 문제가 있다. `mcp/src/index.ts:384`의 `MAX_SINGLE_SHARD_BYTES`는 4MiB이고 2470행에서 적용한다. 현행 hot_search_index의 예금자보호 파일은 14,330,628바이트·45,374행이며, 2566행 보호검색 경로가 해당 파일을 사용한다. 현행 자료와 코드의 자체 크기 제한이 충돌한다.
- 전체 검색 원본 약92.7MB는 요청당 메모리 사용량 측정치가 아니다. 기존 전체판은 분야별 파일을 골라 읽는 구조다. 은행 약0.95MB, 카드0.64MB, 보험1.43MB, 연금3.04MB, 기준정보3.43MB, 지원금1.81MB의 검색 조각이 있으며, 첫 요청의 JSON 파싱·검증 CPU 비용은 별도 검증해야 한다.
- 기존 ID 상세조회용 조각 512개(최대 약222KB)는 재사용 검토 대상이다. 비교·추천과 분리한 전체 분야 search/fetch, 사전 검색색인 생성, 큰 검색 조각 소분할, 필요한 결과 상세만 읽는 방식이 검토 방향이다.
- **확정 결론:** 현재 미제공의 직접 원인은 축소 구현이다. 현재 무료 자원 한도에서 최적화된 전체 검색이 불가능하다는 근거는 확인되지 않았다. 반대로 무료 안정 운영을 통과했다는 증거도 아직 없다. 운영 배포 전 캐시 없는 첫 요청·분야별 검색·다중 조건·ID 조회의 실제 Worker CPU·메모리 검증이 필요하다.
- 원복 검증: 독립 QA가 docs/index.html과 130d7edc의 바이트 일치, 카드 간격 CSS 보존을 확인했다. 원복 커밋은 `c05bb7c1da82ec34eab551aa73c1666f6dfff025`이며 홈페이지 전용 반영이다.
- [Pages 원복 배포](https://github.com/cocomo0412/OpenFin/actions/runs/37613914815) build·deploy 성공. 공개 index.html을 다시 받아 원복 커밋 및 130d7edc 원문과 바이트 일치를 확인했다. SHA-256 `fbb737e37087a54c5710ee1601e70891c48a1b75367412dec02a030ddb67a8a0`. MCP 재배포 없음. 조사 스크립트·원응답·이 후속 보고는 로컬 증적으로 보존한다.
