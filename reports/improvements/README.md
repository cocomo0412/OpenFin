## 관리 규칙

- 폴더: `reports/improvements/YYYY-MM-DD/`, 결과: `review.md`, 첨부: `evidence/`.
- 항목 ID: `OF-YYYYMMDD-NN`. 후속 발견일에도 같은 문제는 기존 ID를 참조한다.
- 각 항목에는 발견일·환경/커밋·재현 단계·관찰 사실·영향·우선순위·증적·권장 조치·재검증 조건·상태를 기록한다.
- 증거 수준은 운영 화면 재현 / 코드와 저장 자료 재현 / 개선 제안 / 미확인으로 구분한다. 재현용 가상 자료의 결과를 운영 피해나 발생 빈도로 표현하지 않는다.
- P1: 잘못된 정보 신뢰·대상 선택으로 이어질 수 있어 우선 검토. P2: 탐색·이해를 방해하는 일반 개선. P3: 경미한 표현 개선. 측정하지 않은 점수를 만들지 않는다.
- 상태: 발견 → 검토 → 로컬 수정 → 검증 → 운영 반영 → 운영 재검증 완료. 제안·보류·재현 안 됨은 사유를 적는다.
- 새 회차는 관찰 시간과 결과를 추가한다. 수정 전 증거는 남기고 수정 후 증거/커밋/배포 링크를 연결한다.
- 화면에는 공개 서비스 내용만 담는다. 키·개인정보·세션 정보는 저장하지 않는다. 원문 자료 수집을 웹 화면 증적 수집으로 대체하지 않는다.
- 탐색과 서비스 수정·배포는 구분한다. 정기 실행을 새로 예약한 것으로 간주하지 않는다.
