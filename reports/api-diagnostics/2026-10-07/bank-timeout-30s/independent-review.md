- 검토 담당: 독립 품질검증 AI 역할. 구현 및 실 API 요청 실행에 참여하지 않음.
- 기준 커밋: `0422c3e6b23f9ca5f783ae29aa52cda3d87e5685` 위 작업 트리 변경
- 판정: **요청 제한 수정과 전체 페이지 재시험 통과**. 자료 반영·운영 배포와 구분한다.

## 코드 및 보안 검토

`scripts/knowledge/collect-finlife-candidates.mjs`의 Finlife 공통 요청 함수에서 `AbortSignal.timeout(15_000)`이 `AbortSignal.timeout(30_000)`으로 바뀌었고, 10월 7일 측정 근거 주석이 추가됐다. 예금·적금, 은행·저축은행 모든 페이지에 요청별 30초 제한이 적용된다. 전체 실행 시간을 30초로 제한하는 변경은 아니다.

`fetch`의 동일 요청 signal이 응답 본문 읽기인 `response.json()`까지 적용된다. 페이지 합계·중복 식별자 검증, 마지막에만 결과를 저장하는 기존 구조, 인증 방식은 바뀌지 않았다. KDIC 별도 10초 제한은 이번 수정 범위가 아니다.

수정으로 인증 URL·API 키를 출력하거나 저장하는 경로는 추가되지 않았다. 진단 기록은 endpoint·그룹·페이지·응답 시간·상태·건수·해시만 저장한다. 실 API 테스트는 `--catalog-only`이며 `--write` 없이 수행됐다.

## 실 API 증적 재검증

실 API 호출은 구현 담당이 실행했다. 독립 검증자는 추가 API 호출 없이 `collector-trace.json`과 현재 파일 해시를 재검증했다. 2026-10-07 16:52:37~16:53:47 한국시간의 9개 요청 모두 HTTP 200, 제공기관 코드 `000`, 본문 읽기 완료이며 30초 미만이었다.

| 구분 | 금융권 | 완료 페이지 | 수집 행 / 제공 총수 | 본문 포함 요청 시간 |
| --- | --- | --- | --- | --- |
| 예금 | 은행 | 1 | 39 / 39 | 0.755초 |
| 예금 | 저축은행 | 1~4 | 393 / 393 | 0.620~0.653초 |
| 적금 | 은행 | 1 | 59 / 59 | 17.312초 |
| 적금 | 저축은행 | 1~3 | 276 / 276 | 16.051~16.593초 |

각 그룹의 연속 페이지, 페이지별 일정한 제공 총수, 수집 행 합계 일치를 별도 검증했다. 예금 432건, 적금 335건, 합계 767건이다. 적금 4개 요청 모두 기존 15초를 초과했고 변경된 30초 안에 완료됐다.

진단 전 해시와 현재 해시를 독립 비교하여 후보 스냅샷, 공개 수집 현황, 공개 manifest 세 파일이 모두 그대로임을 확인했다. 따라서 이 시험은 홈페이지의 예·적금 수집일을 새 날짜로 바꾸지 않았다.
