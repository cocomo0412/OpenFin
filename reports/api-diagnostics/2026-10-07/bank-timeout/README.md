# 예·적금 수집 시간 초과 원인 분석

확인일: 2026-10-07 (한국시간). 공식 금융감독원 API 진단이며 자료 재수집·발행은 하지 않았다.

## 결론

OpenFin 수집기의 요청당 15초 제한이 이번 재현에서 정상 적금 응답보다 짧았다. `scripts/knowledge/collect-finlife-candidates.mjs`의 `AbortSignal.timeout(15_000)`은 제공기관이 통지한 제한이 아니라 클라이언트 설정이다. Git 이력상 2026-09-23 커밋 `44f34b5d1cbeeaa13022b4e85c36829538e167ad`에서 추가됐다. 커밋 계정만으로 실제 작성자가 사람인지 AI인지 판단하지 않는다.

| 요청 | 제한 | 결과 |
| --- | --- | --- |
| 은행 예금 첫 페이지 | 15초 | 0.740초, 정상 39건 |
| 저축은행 예금 1~4페이지 | 각 15초 | 각 0.663~1.433초, 정상 합계 393건 |

수집기는 예금 다음 적금을 처리하며 전체 완료 후 파일을 저장한다. 따라서 예금 요청이 성공해도 적금에서 중단되면 예·적금 갱신 전체가 반영되지 않는다. 이번 성공 응답으로 해당 요청의 API 주소·인증이 유효함을 확인했다.

## 증적과 범위

- `collector-trace.json`: 기존 수집기 그대로 실행, `--write` 없이 6요청 추적. 자료 파일 변경 없음 확인.
- `timing-probes.json`, `timing-savings-bank.json`: 추가 3요청으로 제한 시간별 결과 비교. 원문 응답·인증키·인증 URL 미기록.
- `trace-collector.mjs`, `probe-timing.mjs`: 재현용 진단 도구. 비공개 환경변수를 이용하며 실제 수집 코드의 제한은 변경하지 않는다.
- 이전 실패 로그에는 요청별 주소·페이지가 없어 당시 실패 지점을 확정할 수 없다. 위 재현은 당시 약 19초의 전체 실패 시간과 일치하는 원인을 확인한 것이다.
- 저축은행 적금은 첫 페이지만 진단했으므로 전체 276건의 완전 수집 검증이 아니다. 제공기관 내부 지연 원인은 확인되지 않았다.

## 조치 제안과 현재 상태

요청 제한을 30~45초로 조정하고 일시 오류에만 제한적으로 재시도하며, 인증정보를 제외한 요청 종류·업권·페이지·실패 단계·시간을 기록하는 것이 적절하다. 무제한 대기·재시도는 사용하지 않는다. 이번 작업은 원인 분석이며 실제 제한 변경과 전체 재수집은 수행하지 않았다. 기존 정상 자료 및 수집일을 유지했다.

진단만으로 홈페이지·MCP 배포는 필요하지 않다. 별도 자료 버전 수정의 홈페이지 배포 여부는 해당 개선 기록에서 관리한다.
