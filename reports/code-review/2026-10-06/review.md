# OpenFin 개발 및 보안 코드 검토

검토일: 2026년 10월 6일 한국시간. 서비스 코드 수정과 배포 없이 현행 저장소의 코드 목록, 개발·보안 위험, 수정 필요사항을 검토했다. **조치 항목 12건**을 기록했으며 모두 미조치 상태다. 의존성 갱신, 수집 완전성 검사, 갱신 중단 시 자료 보존을 우선할 것을 제안한다. 현재 무료 MCP에서 원격 악용을 입증한 고위험 취약점이나 이번 패턴 검사에서 확인된 실제 API 키 노출은 없었다. 이는 보안 인증이나 취약점 부재 보장이 아니다.

사용자 요청에 따라 기존 프로젝트팀 5개 역할에 **개발보안팀 2개 역할**을 추가했다. 보안 설계·구현 검토 담당은 위험과 조치안을 검토하고, 독립 보안 검증 담당은 재현 조건과 수정 결과를 확인한다. 총 7개 역할이며 같은 변경의 구현자와 최종 보안 검증자는 분리한다. [팀 지침](../../../AGENTS.md), [개발 매뉴얼](../../../handbook/development.md), [운영 매뉴얼](../../../handbook/operations.md)에 반영했으며 공통 매뉴얼 버전은 **1.3.0**이다.

## 검사 결과와 확인한 보호 동작

- 안전하게 실행 가능한 기존 검사 **189개 중 187개 통과, 2개 실패**. MCP 119/119, 파이프라인 29/29, 웹 39/41이다. 실패 2개는 SEC-07로 남겼다. 전체 테스트를 모두 실행한 결과는 아니다.
- MCP 타입 검사와 웹 JavaScript 8개 구문 검사는 통과했다. 실제 데이터를 덮어쓰는 빌드·갱신·일부 검사와 운영 부하 검사는 실행하지 않았다.
- JSON 문법 오류 0개. 비밀정보 패턴 후보 40건은 모두 금융상품 식별자의 오탐으로 분류했다. 검사 범위와 한계는 [저장소 검사](repository-checks.md)에 있다.
- 기본 자료 갱신에 HTML·PDF 수집의 자동 대체 경로가 연결되지 않은 것을 확인했다. API 실패 시 이전 정상 자료와 원래 날짜를 유지하는 처리도 확인했다. 기관 API를 실제 재요청하거나 최신 규격을 재검증한 회차는 아니다.
- 현재 무료 MCP는 search·fetch·exports만 제공하고 요청 크기·입력 길이 제한이 있다. 공개 검색어의 직접 HTML 삽입 경로나 외부 PR에 배포 secret을 넘기는 현행 CI 경로는 확인하지 못했다.

원격 권한·실제 요청 제한·통계 수집 payload·Git 과거 이력·vendor 갱신 정책은 [별도 확인 목록](repository-checks.md)에 남겼다. 조치 목록 12건과 별개이며 확정 취약점으로 집계하지 않는다.

## 변경 및 배포 상태

| 대상 | 이번 변경 | 이번 배포 | 후속 판단 |
| --- | --- | --- | --- |
| 팀 지침·매뉴얼·검토 기록 | 로컬 문서와 증적만 작성, 매뉴얼 1.3.0 | 배포 불필요 | 원격 반영 여부 별도 관리 |
| 홈페이지 | 서비스 코드·공개 데이터 변경 없음 | 배포하지 않음 | URL 렌더러 또는 공개 생성 데이터가 바뀌면 반영 필요 |

수집기 수정은 그 자체로 홈페이지나 MCP 재배포를 뜻하지 않는다. 이후 검증된 공개 데이터와 무료 카탈로그에 어떤 변화가 생겼는지로 각각 판단한다. 기존 미배포 변경까지 함께 반영한다면 전체 묶음을 다시 확인한다. 이번 회차는 commit·push·배포를 수행하지 않았다.

최종 파일 범위와 서비스 코드 불변 확인은 [verification.json](verification.json), 증적 파일 해시는 [evidence-manifest.json](evidence-manifest.json)에 남겼다.
